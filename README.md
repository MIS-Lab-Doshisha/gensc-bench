# gensc-bench

This benchmark compares the topological fidelity of graphs generated by VAE, WGAN-GP, and DDPM on five synthetic graph families and AAL116 structural connectivity (SC) from NIMH and HCP Young Adult.

Paper: [Comparative Evaluation of Deep Generative Models for Capturing Topological Features in Brain Structural Connectivity Matrices](https://www.biorxiv.org/content/10.64898/2026.06.03.729714v1)

## Repository structure

```text
.
├── config/
│   ├── vae/             # VAE training settings by dataset
│   ├── gan/             # GAN training settings by dataset
│   ├── ddpm/            # DDPM training settings by dataset
│   └── paths.yaml       # Dataset paths, evaluation runs, and output roots
├── data/
│   ├── binary/
│   │   └── raw/         # Binary synthetic graph archives
│   ├── continuous/
│   │   └── raw/         # Continuous synthetic graph archives
│   └── sc/              # NIMH benchmark input
├── dataset/             # Data preparation and split export
├── reconstruction/      # HCP reconstruction
├── model/               # Model definitions
├── train/               # Training
├── gen/                 # Sampling
└── eval/                # Thresholding, metrics, and figures
```

## 1. Environment

Run commands from the repository root unless shown otherwise. The experiments were conducted using an NVIDIA GeForce RTX 4080 SUPER GPU. The host NVIDIA driver version was 550.90.07. The Docker environment uses Ubuntu 22.04, CUDA 12.1.1, cuDNN 8, and Python 3.10.13. Python package versions are specified in `requirements.txt`.

```bash
docker compose build
docker compose run --rm dev
```

For a local Python 3.10.13 environment, install the dependencies in [requirements.txt](requirements.txt).

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

For Orbit MMD, download the ORCA executable from the [GraphRNN repository](https://github.com/JiaxuanYou/graph-generation#evaluation) and place it at `eval/orca/`.

## 2. Data

This repository includes the original benchmark input datasets for all five synthetic graph families and the NIMH SC dataset. These datasets can be used directly to reproduce the experiments without additional data preparation. The HCP SC dataset is not included and must be reconstructed from the HCP Young Adult S1200 release using the procedure described below.

| Dataset key | Input |
| --- | --- |
| `ba` | `data/binary/raw/ba_dfs_adj_matrix.npz` |
| `planar` | `data/binary/raw/planar_dfs_adj_matrix_all.npz` |
| `sbm` | `data/binary/raw/sbm_adj_matrix.npz` |
| `ws` | `data/binary/raw/ws_kcore_adj_matrix.npz` |
| `wba` (WSF) | `data/continuous/raw/wba_dence_dfs_adj_matrix.npz` |
| `nimh` | `data/sc/input_dict.pkl` |
| `hcp` | `data/hcp/raw/hcp_mat_data.npz` (reconstruct locally) |

### HCP-YA S1200 reconstruction

SC matrices for the HCP dataset were reconstructed from the preprocessed diffusion-weighted and anatomical MRI data in the HCP Young Adult S1200 release.All subjects with the required diffusion MRI data were included, without additional exclusion based on reconstruction outcomes. Subjects were processed in ascending numerical order of their HCP subject IDs.

Obtain preprocessed diffusion and anatomical data through ConnectomeDB. The script uses Bash and the official `mrtrix3/mrtrix3:3.0.8` Docker image as supplied, with its FSL tools. See the paper for reconstruction methods. [HCP Young Adult S1200 release](https://www.humanconnectome.org/study/hcp-young-adult/document/1200-subjects-data-release)

Before running the pipeline, use MRtrix's `labelconvert` to relabel the AAL 1 atlas for SPM12 (`aal/atlas/AAL.nii`) in standard space. Assign contiguous node IDs 1–116 in the order listed in `ROI_MNI_V4.txt`. Set the `atlas` variable in `reconstruction/pipeline.sh` to the path of the converted atlas as seen from the Docker container. [AAL distribution](https://www.gin.cnrs.fr/en/tools/aal/) · [MRtrix labelconvert](https://userdocs.mrtrix.org/en/doctest/reference/commands/labelconvert.html)

By default, `reconstruction/mrtrix_env.sh` mounts the host's `$HOME/data` at `/data` in the container. To use another data directory, update the mount in `mrtrix_env.sh` and use that directory in the commands below. Store the HCP inputs under your data directory with the following layout.

```text
hcp/batch_000/raw/<SUBJECT_ID>/
  T1w/
    Diffusion/data.nii.gz
    Diffusion/bvecs
    Diffusion/bvals
    Diffusion/nodif_brain_mask.nii.gz
    T1w_acpc_dc_restore_brain.nii.gz
  MNINonLinear/xfms/standard2acpc_dc.nii.gz
```

From your data directory, run the pipeline. Replace `/path/to/repo` with the repository path. The argument `0` selects `batch_000`.

```bash
PATH="/path/to/repo/reconstruction:$PATH" bash /path/to/repo/reconstruction/pipeline.sh 0
```

From the repository root, convert the CSVs in `hcp/output/` to one NPZ. The converter reads all CSVs there in filename order, including any left from previous runs. If you changed the data directory, replace `$HOME/data` below with its path.

```bash
python -m dataset.preprocess --csv_path "$HOME/data/hcp/output" \
  --npz_path_stem data/hcp/raw --npz_filename hcp_mat_data.npz
```

## 3. Splits and seeds

The test set is fixed across runs. The synthetic and HCP datasets reserve 20% for testing, with split seeds 60 and 42 respectively. NIMH reserves 27 of 107 subjects. Each run uses one of the four discovery folds for validation. Runs are indexed from 0 to 3 in the repository, corresponding to runs 1–4 in the paper.

| Artifact | Validation fold | Training seed |
| --- | ---: | ---: |
| `run_0` | 0 | 42 |
| `run_1` | 1 | 43 |
| `run_2` | 2 | 44 |
| `run_3` | 3 | 45 |

Optuna uses seed 1. The sampling seeds are 90 for VAE and 91 for WGAN-GP and DDPM.

The repository includes `split_indices.yaml`, containing the discovery and test set indices for each dataset. These indices can also be regenerated from the original datasets using the following command:

```bash
python -m dataset.export_split_indices
```
Training and validation sets within the discovery set are determined by the four-fold splitting procedure implemented in the training code.

## 4. Training and sampling

For each dataset, set `ds` to its key from the data table. The first command tunes and trains `run_0`. The second reuses `best_params.json` for `run_1` through `run_3`. Training automatically generates 1,000 adjacency matrices per run in `checkpoints/fix/<dataset>/<model>/run_<index>/generated_graphs.npz`.

```bash
ds=ba
for model in vae gan ddpm; do
  python -m "train.train_${model}" --config_path "config/${model}/${ds}.yaml" --optimize || break
  python -m "train.train_${model}" --config_path "config/${model}/${ds}.yaml" || break
done
```

## 5. Evaluation

Run these commands after sampling. They use [config/paths.yaml](config/paths.yaml) and write results under `output/`.

### 5.1 Evaluation preparation

Threshold the synthetic samples before plotting or computing metrics.

```bash
python -m eval.evaluate --path_config config/paths.yaml --datasets ba planar sbm ws wba --thresh
```

### 5.2 Mean adjacency plots and Individual adjacency plots

The `--mean` option shares a single color scale across all datasets specified in one run. To reproduce the paper figures, run the commands separately for the synthetic datasets, HCP, and NIMH.

```bash
python -m eval.vis --path_config config/paths.yaml --datasets ba planar sbm ws wba --mean
python -m eval.vis --path_config config/paths.yaml --datasets hcp --mean
python -m eval.vis --path_config config/paths.yaml --datasets nimh --mean
```

Omit `--datasets` to plot individual adjacency matrices for all datasets in the path configuration.

```bash
python -m eval.vis --path_config config/paths.yaml --plot_graphs # individual adjacency plots
```

### 5.4 MMD and planarity

Install ORCA before computing MMD. Run MMD before appending strength and planarity to its CSVs.

```bash
# MMD
python -m eval.evaluate --path_config config/paths.yaml --datasets ba planar sbm ws wba nimh hcp --mmds # it should be run first to generate the MMD CSVs
# Strength (WBA only)
python -m eval.evaluate --path_config config/paths.yaml --datasets wba --strength
# Planarity (Planar only)
python -m eval.evaluate --path_config config/paths.yaml --datasets planar --planarity
```
Embedding MMD is computed using the external implementation provided by Thompson et al. (2022). The external implementation requires a separate environment. Refer to the original repository for installation instructions.

### 5.5 Modularity and small-worldness (sigma)

```bash
python -m eval.evaluate --path_config config/paths.yaml --datasets sbm nimh hcp --modularity
python -m eval.calc_sigma --path_config config/paths.yaml --datasets ws nimh hcp
```

### 5.6 Hub and strong-edge preservation

```bash
python -m eval.evaluate --path_config config/paths.yaml --datasets nimh hcp --hub --jaccard
```

### 5.7 Edge-wise variability, pairwise distances, and nearest neighbors

```bash
python -m eval.vis --path_config config/paths.yaml --datasets nimh hcp --edge_var
python -m eval.evaluate --path_config config/paths.yaml --datasets nimh hcp --pdist --nn
```
